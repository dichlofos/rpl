# LRPL

Локальное Python-приложение для подготовки фотографий к отчёту RPL. Оно умеет
быстро прочитать время и камеру из EXIF, подключиться к Центру, выбрать
путешествие, предложить временную поправку для каждой камеры и пакетно
привязать фотографии к выбранным трекам. Метаданные и стабильные локальные
идентификаторы сохраняются в SQLite, а Центр назначает кадрам `photo_key`.

Установите зависимости для фотопрототипа:

```bash
python -m pip install -e '.[photos]'
```

## Локальная веб-панель

Сначала примените миграции Центра и выпустите персональный токен:

```bash
python manage.py migrate
python manage.py create_lrpl_token USERNAME --name "My laptop"
```

Затем запустите LRPL, указав каталог фотографий и адрес Центра:

```bash
python -m lrpl web /path/to/photos --center-url https://rpl.example/
```

LRPL слушает случайный свободный порт только на `127.0.0.1` и открывает
панель в системном браузере. Токен вводится в панели и пока хранится только в
памяти процесса. Удалённый Центр обязательно должен использовать HTTPS;
обычный HTTP разрешён только для локальной разработки.

Панель показывает предложенную поправку в соглашении
`нормализованное время = время EXIF + поправка`, а после обработки группирует
результаты как `matched`, `ambiguous`, `unmatched` и `invalid`. В Центр уходят
только идентификаторы, файловые признаки, временные метки и вычисленная
геопривязка — сами фотографии не загружаются. Если в EXIF есть GPS, он имеет
приоритет; иначе координаты интерполируются по выбранным трекам. Повторная
отправка той же локальной пачки обновляет её, не создавая дубликатов.

После привязки панель предлагает логические дни `01`–`99`. За основу берутся
календарные даты выбранных треков и исправленное время фотографии; если у
отчёта нет датированных треков, используются даты исправленного времени.
Предложения можно подтвердить всей пачкой либо изменить для отдельного кадра.
Подтверждённая ручная правка сохраняется при повторной калибровке. Таблица
расположена хронологически и разбита на страницы по 500 фотографий.

SQLite-индекс, технический вращаемый лог и продуктовый JSONL-журнал находятся
в стандартном каталоге данных приложения ОС. При следующем запуске неизменённые
JPEG не читаются повторно. Точный путь печатается при запуске; для тестов его
можно переопределить переменной `LRPL_STATE_DIR`.

## Исследовательский CLI

Тяжёлый анализ SHA-256, perceptual hash, резкости и похожих кадров остаётся
доступен прежней командой:

```bash
python -m lrpl /path/to/photos \
  --gpx /path/to/day-01.gpx \
  --gpx /path/to/day-02.gpx
```

Полный машиночитаемый результат:

```bash
python -m lrpl /path/to/photos --gpx /path/to/track.gpx --json
```

Поправка времени определяется соглашением:

```text
нормализованное время = исходное время EXIF + поправка
```

Например, для камеры, показывающей местное `12:00`, и точки трека `09:00Z`
поправка равна `-03:00`.

По умолчанию соседние кадры одной камеры с разрывом не более 10 секунд входят
в один временной эпизод. Внутри него точные и визуально близкие фотографии
собираются в более узкие стопки. Порогами можно управлять параметрами
`--episode-gap-seconds`, `--difference-hash-distance` и
`--perceptual-hash-distance`.

Текущие отпечатки, оценка резкости и ранжирование поправок — исходные алгоритмы
для проверки на реальных данных, а не окончательные продуктовые пороги. EXIF
исходных файлов не изменяется.
